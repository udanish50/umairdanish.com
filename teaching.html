Teaching

Learning machine learning by building, debugging, and explaining.

I teach code as a medium for reasoning: students frame a problem, establish a baseline, implement carefully, inspect failures, and communicate evidence.

Teaching philosophy

Code should make theory visible.

My central belief is that students learn machine learning most deeply when code becomes a way to test ideas—not merely a tool for producing predictions. I connect intuition, mathematical structure, and executable experiments, asking students to predict behavior before running code and to explain differences between expectation and evidence.

“A model is a claim about data. Students should learn to express that claim in code, test it against evidence, diagnose its failures, and explain when it should—and should not—guide a decision.”

Learning design

Principles that guide my classroom

Start simple, then earn complexity

Meaningful baselines come before sophisticated models. Students must explain why a simple method fails before claiming that complexity adds value.

Treat debugging as intellectual work

Students localize failures, state hypotheses, design tests, and document fixes—developing independence and engineering judgment.

Assess authentic workflows

Projects include data validation, version control, reproducible experiments, error analysis, and concise stakeholder communication.

Build responsible judgment into code

Privacy, leakage, subgroup performance, uncertainty, drift, and the cost of errors are part of technical assignments, not separate afterthoughts.
